# Product gaps — Phase 0 red end-to-end tests (Phases 1–2)

Phase 0 item 5 of `docs/team-prompts/product-gaps-fix-prompt.md`, Playwright half: one file per PG item in `tests/acceptance/product-gaps/`, run by the acceptance Playwright config against the real engine (temp data dir, mock provider) and the production web build. Shared seeding and page helpers are in `helpers.ts`. It does not end in `.e2e.ts`, so it is not collected as a test file.

Each test is `test.fail(NOT_BUILT, '<PG id>: …')`. Each one passes while its feature is missing, and if the feature lands without the marker being removed, Playwright reports an unexpected pass, so the test cannot be left behind. `PG_PROVE_RED=1` turns the markers off so the tests run as ordinary tests. That is how each failure line below was read.

```
# red, as committed: every test an expected failure
ACE_ACCEPTANCE_PORT=47620 pnpm exec playwright test --config tests/acceptance/playwright.config.ts product-gaps
#   40 passed (6.0m)
# the proof: markers off, read what each one fails on
PG_PROVE_RED=1 ACE_ACCEPTANCE_PORT=47620 pnpm exec playwright test --config tests/acceptance/playwright.config.ts product-gaps --retries=0
#   40 failed
```

Expectations wait 5 s (`expect.configure`). This makes a missing control fail quickly and at that control. In every row, the setup steps before the failing line passed: seeding through the API, opening the page, opening dialogs, sending the chat and starting the run. Three rows also carry an explicit proof that the precondition held (2.1, 2.4 and 1.5 Domain). These are noted in the table.

## Notes for whoever turns these green

- **The "Tests" lists in the prompt are not all Playwright.** This file covers only the Playwright ones. The Vitest ones are not here: the `providerGroup` unit tests, the engine "a throw after acceptance stores a failed turn", the chat-route contract tests, the "superseded or deleted message never reaches the next prompt" engine test, and the "no code path builds `bypassPermissions`" test.
- **PG-1.2 uses no axe.** `@axe-core/playwright` is not installed, and adding it would change the workspace lockfile for one test. `pg-1-2-visible.e2e.ts` instead scans each page for the two rule families PG-1.2 names: an accessible name on every control, and WCAG AA text contrast (4.5:1, or 3:1 for large text) against the nearest opaque background. It also applies the prompt's glyph rule. Within this suite, that glyph rule is the "fails on any unicode glyph inside a `<button>`" test. A source-level lint rule can still be added in Phase 1. If axe is added later, it replaces `scan()` and the assertion stays. The contrast check is narrower than axe. It checks control text only, not icon or border contrast (3:1), so a clean scan here is not yet the prompt's audit.
- **PG-1.1 zoom is the Canvas zoom.** The viewport scale is set with the toolbar's Zoom in/out to 1.0 and 0.5. Browser zoom is not used.
- **PG-1.4 uses a stand-in for MSW.** The prompt names MSW for the Ollama tags. This suite drives the real engine, so a loopback HTTP server stands in for Ollama (`/v1/models`, `/api/tags`).
- **PG-1.5 Ideate failure was dropped as a PG-1.5 symptom.** A failing model in Ideate chat is already shown as a stored failed turn (D287), so it is not PG-1.5's symptom. It lives in PG-1.6 as "a failed turn is shown, and Retry on it runs the turn again", and its first assertion passes today. The engine path that escapes (a throw after 202 in guardrails, usage or store) is not reachable from the UI with the mock. It belongs to the Vitest red test.
- **The PG-1.5 "run has ended" test may need a change after PG-3.3.** It relies on Domain not hearing the run end, which is PG-3.3's bug, so the page still offers Send and the real engine answers 409. Once PG-3.3 makes Domain hear `run.completed`, that path needs another way to reach a 409. One option is to post before the frame arrives.
- **PG-2.4 forces the checkpoint failure.** A plain file is placed at `<dataDir>/checkpoints/<projectId>.git`, which makes the git store's `mkdir` fail. The project folder stays healthy.
- `tests/acceptance/tsconfig.json` now includes `product-gaps`, so `tsc --build` typechecks this folder. `domain/` is still not included, as before.
